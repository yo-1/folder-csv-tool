# フォルダ・ファイル一覧CSV作成ツール

Folder CSV Tool v1.3.1 ― 先行改修A・実機確認前

指定フォルダ内の全階層の一覧を取得し、分割CSVと管理JSONに保存するWindows用Pythonツールです。ローカルフォルダと、アクセス権のあるNASのUNCパスに対応します。元データの修復・変換・削除や、内部品質検査は行いません。

## 起動と保存

必要環境はPython 3（tkinter付き）。追加pipパッケージは不要です。

1. ZIPを展開して `start.bat` を起動します。
2. 対象フォルダと保存先を入力します。保存先はPCローカル側を推奨します。
3. 1CSVのデータ行数を選択します。初期値は10万行です。
4. 「一覧を取得」を押します。件数、経過時間、現在対象、最終応答を表示します。
5. 終了状態を確認して「保存フォルダーを開く」「終了概要を開く」を使います。
6. 続ける場合は「新しい一覧を取得」、閉じる場合は「終了」を押します。

出力先の下に、日時＋UUIDの取得IDごとのフォルダを作ります。毎回別のフォルダに保存するため、以前の結果は上書きしません。

```bat
py -3 folder_csv.py --root "C:\GIS\Data" --output-dir "C:\Work\Inventory" --rows-per-csv 100000
```

`--rows-per-csv` は10000／50000／100000／0（分割なし）。v1.2の `--output`（単一CSV指定）は、v1.3.1では `--output-dir`（成果物セットの保存先）に変更しました。

## 出力

| ファイル | 内容 |
|---|---|
| `<取得ID>_00001.csv` 等 | 確定済み分割CSV。UTF-8 BOM付き |
| `<取得ID>.manifest.json` | 精査アプリへ渡す管理JSON |
| `<取得ID>.errors.csv` | 取得エラー。0件でも見出しのみを保存 |
| `<取得ID>.scopes.jsonl` | 失敗・未走査・リンク省略範囲。1行1JSON |
| `<取得ID>.summary.txt` | 終了概要・出力一覧 |
| `<取得ID>.work.sqlite` | 待ちフォルダの一時管理。再開用ではない |

書込中のCSVは `.csv.part` です。確定保存後に `.csv` に改名します。管理JSONが正常終了しているか、各分割が確定しているかを確認してください。`.csv.part` を完了成果物として読み込まないでください。

## CSVの列（A～Iを維持）

| 列 | 名前 | 内容 |
|---|---|---|
| A | 種別 | ファイル／フォルダ／リンク／不明 |
| B | 名前 | 項目名。単独では一意なキーではない |
| C | 相対パス | 指定ルート基準。ルート自身の行は含まない |
| D | フルパス | 原本へのアクセス用 |
| E | 拡張子 | 処理用。拡張子のみ。フォルダ／拡張子なしは空欄 |
| F | サイズ_バイト | ファイルの整数サイズ。空ファイルは0、取得不能・フォルダは空欄 |
| G | 更新日時 | 既存のISO形式・秒精度・実行PCローカル時刻を維持 |
| H | 表示分類 | 目視用。拡張子／フォルダ／拡張子なし／リンク／不明 |
| I | 状態 | 次の対応表参照 |

| I列の値 | 意味 |
|---|---|
| 取得済み | 当該項目の情報を取得。配下の完全性は範囲記録で別途確認 |
| 取得エラー | 当該項目の情報取得に失敗 |
| フォルダ列挙失敗 | フォルダの情報は取得したが、内部列挙に失敗・不完全 |
| 配下未走査 | フォルダ列挙を中断。配下の完全性は未確認 |
| リンク先の再帰走査は省略 | 参照先を意図的に走査しない |

未知の状態は正常と解釈しません。状態のない旧CSVも、取得時の状態が未記録であることを検査側に伝えてください。

## 分割と集計

行数は見出しを除き、ファイル・フォルダ・リンク・不明の全レコードを数えます。フォルダの意味を推測せず、ルート直下のファイルも同じルールで分割します。フォルダの途中でCSVが切り替わります。分割ごとに再走査しません。

リンクは独立した種別とし、ファイル／フォルダに重複計上しません。

`processed_rows = files + folders + links + unknown`

`confirmed_rows = 確定分割CSVのdata_rowsの合計`

ファイル容量の合計は、情報取得して出力処理したファイルのサイズ合計です。異常終了時は未確定分割も含むことがあるため、処理済みと確定済みを区別してください。CSV記載順は走査順であり、フォルダ行は配下列挙後に記録します。

## 終了状態・中断

| 管理JSONのrun_status | 表示 |
|---|---|
| running | 取得中。異常停止後もこの値が残る可能性あり |
| completed | 設定どおり正常完了。リンク先省略は別途確認 |
| partial_failure | 一部取得失敗 |
| interrupted | 中断 |
| abnormal | 異常終了・保存失敗 |
| not_started | ルートへアクセスできず未開始 |

取得中の「中断」はOSアクセスが戻った時点で受け付け、取得済み行を確定保存します。**SMB通信待ちを即時に強制停止する機能、再試行、チェックポイントからの再開は未実装です。** 応答通知が15秒以上ないと「応答待ち」と表示しますが、NAS障害と断定しません。

画面からの通常中断後の再実行は新規取得IDで最初から取得します。CLIのCtrl+Cでは、書込途中の分割を未確定のまま残す場合があります。電源断・強制終了では、管理JSONが `running` のまま残ったり、未確定CSVが残ったりします。完了と扱わないでください。出力ボリューム自体が使用不能になると最終JSON・概要を書けない場合があります。

隠し・システム属性の項目を含めます。リンク／Windowsリパースポイントは追跡せず省略を記録します。指定ルート自身は利用者が明示した入力としてアクセスします。全項目が同一時点の状態であることは保証しません。

## 精査アプリとの連携

**管理JSONを入口にして全分割を列名で読みます。H列は形式判定に使いません。** 分割をまたぐ付属ファイルの照合には、取得IDと相対パスを利用します。

詳細は [連携仕様](docs/inventory-contract.md)、機械可読の状態対応は [status_spec.json](docs/status_spec.json) を参照してください。未走査・取得不能を不存在／良品として扱わない契約です。

## 確認状況

人工データと障害注入による自動試験を実施しました。847,411行は10万行×8＋47,411行の9CSVになり、レコードの重複・欠落がないことを確認しました。条件と未確認事項は [試験記録](docs/validation.md) を参照してください。

Windowsの実画面・実NASでの改修版の確認は未実施です。v1.2での約85万行取得成功は、この改修版の実機合格の代わりにはしません。

## 起動できない場合

start.batはlaunch.ps1を使い、登録済みPythonを順に確認します。tkinterのimportとTcl/Tkの画面初期化を確認し、利用できるPythonで起動します。自動インストールはしません。

見つからない場合は、表示されたstartup診断ログを添付してください。Python未導入・未検出とtkinter/Tcl-Tkのエラーを区別します。ログはLocalAppData/FolderCSVToolへ保存します。Pythonを指定する場合はツールと同じフォルダにpython_path.txtを作り、python.exeのフルパスを1行で記載します。QGIS付属Pythonにはtkinterがない場合があります。

PowerShellのExecutionPolicy Bypassは起動プロセスだけに指定し、PCの恒久設定は変更しません。組織ポリシーで制限される場合はPythonからfolder_csv.pyを直接起動してください。
